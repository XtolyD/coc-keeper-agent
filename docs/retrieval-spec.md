# 规则书检索规范（M2 · RAG 分块与索引）

> 本文档定义规则书从「清洗文本」到「可检索规则块」的规范。
> 规则书处理是**离线一次性**的：分块、建索引都在脚本中完成，运行时只加载索引。
> 模组处理与本流程**完全分离**，另由模组抽取管道负责。

## 0. 目标

让 `search_rules(query)` 能返回**精准、可回溯页号**的规则命中，例如：

- 查「奖励骰怎么掷」→ 命中「5.8 奖励骰与惩罚骰」小节块，引用页 p76-78
- 查「食尸鬼」→ 命中「食尸鬼」怪物块，引用页 p266
- 查「闪避」→ 命中「闪避」技能块，引用页 p44

## 1. 设计原则

1. **按内容实体分块，而非按 TOC 页区间**。
   TOC 章节只作为「归属路径」（章节路径），真正的检索单元是**内容实体**：
   怪物、技能、法术、小节、表格、词条。
2. **每块携带元数据**，检索命中即可引用：`{实体类型, 名称, 章节路径, 页码, 原文}`。
3. **只保留规则正文**：前言/目录/使用说明/版权页/译者/引文署名一律排除。
4. **可测**：分块逻辑是纯函数，单元测试锁定边界识别。

## 2. 数据流

```
PDF ──(extract_rules.py)──► rules_pages/*.txt  每页清洗文本
                       └──► rules_structure.json  TOC 分层（章节路径）
                                      │
                         (chunk_rulebook.py  离线)
                                      ▼
                    rules_chunks.json   实体块 + 元数据
                                      │
                         (build_index.py  离线)
                                      ▼
                    rules_bm25.index    序列化 BM25 索引
                                      │
                              search_rules()  ← 只读索引，不重算
```

## 3. 实体分块规则

按「信号」自动识别块边界，优先级从高到低：

### 3.1 字号/字体变化 → 新实体（最高优先）
- **标题**：字号 > 正文（正文约 10.6pt，标题 12~16pt），或字体不同（如怪物名用
  `DengXian-Light`，正文 `MicrosoftYaHeiLight`）。
- 作为**新块起点**，且该行文本即实体名/标题。

### 3.2 命名规律 → 实体名（怪物/技能/法术）
- 怪物名：紧接属性块的独立短标题行。
- 技能条目：`名称（基础值）` 或 `名称（xx%）`（如 `闪避（一半DEX）`）。
- 法术：`法术名` 独占标题 + 后续消耗/效果段。

### 3.3 关键字特征 → 块内结构化段
这些**不断块**，但标记段类型（供展示/排序）：
- `STR/CON/DEX/INT/POW/SIZ/EDU …` → 属性
- `格斗/闪避/护甲/技能/理智丧失/法术/移动` → 战斗数据
- `特殊能力`、`法术：`、`例子：` → 能力说明

### 3.4 段落/空行 → 次要边界
同一实体内的自然段落，作为「子段落」，用于控制块大小。

## 4. 块类型（EntityType）

| 类型 | 章节来源 | 示例 |
|---|---|---|
| `skill` | 第四章 技能 | 闪避、侦查、格斗 |
| `combat` | 第六章 战斗 | 战技、射击、伤害 |
| `monster` | 第十四章 怪物 | 拜亚基、食尸鬼、昌格纳·方庚 |
| `spell` | 第十二章 法术 | 放逐术、召唤术 |
| `tome` | 第十一章 神话典籍 | 死灵书、黄衣之王 |
| `rule` | 其余章节（检定/理智/追逐等） | 奖励骰、临时疯狂、追逐轮 |
| `table` | 表格页（表Ⅰ~表XVI） | 伤害加值表、武器列表 |
| `glossary` | 附录Ⅰ 术语表 | 「护甲」「奖励骰」词条 |

## 5. 分块算法（示意）

```
for each cleaned page P:
    blocks = detect_blocks(P)          # 按 字号/字体/段落 识别候选块
    for block in blocks:
        t, name = classify(block)       # 定 实体类型 + 名称
        chunk = {
            "type": t, "name": name,
            "path": section_path(block),   # 章节路径（来自 TOC）
            "page": P.page_no,
            "text": block.text,
        }
    # 合并/拆分：超大块（>800 字）按段拆分，小块(<80字)并入相邻
```

- **块大小目标**：200~600 字。过大影响 BM25 精度，过小失去上下文。
- **超长列表**（如技能列表、怪物全表）：保留整页为一个实体块，但块内标记
  item_start，供检索命中后定位具体条;同时**按条目**提供独立子块。

## 6. 检索算法（BM25）

- **自实现纯 BM25**（零依赖，符合项目学习定位；比 `rank_bm25` 更可控、可测）。
- 字段：对每个块建索引；检索时对 query 做同样分词（中文按字/词）。
- 评分 = BM25(title) × w1 + BM25(text) × w2，标题命中权重更高。
- 返回 top-k 块，附 `{type,name,page,path,snippet}`。

## 7. 排除清单（非规则内容，不建索引）

- 前言、目录、使用说明、版权页、致谢、译名表、汉化进度表
- 章节标题行（作为块的 path 而非正文）
- 译者署名、洛夫克拉夫特引文及署名

## 8. 对外接口

```python
search_rules(query: str, top_k: int = 5) -> list[RuleHit]
# RuleHit = {type, name, page, path, snippet, score}
```

运行时**只加载**构建好的 `rules_bm25.index` + `rules_chunks.json`，
不读取 PDF、不执行分块，保证离线/在线分离与检索速度。
